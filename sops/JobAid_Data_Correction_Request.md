# Job Aid: Processing an Employee Data Correction Request

**Use this when:** A ticket comes in requesting a correction to an employee's record (department, manager, name, hire date, etc.)

## Steps

1. **Verify the requestor's authority**
   Confirm the request comes from the employee's HRBP, manager, or the employee themselves via the approved channel (shared mailbox or ticketing tool). Do not action requests from unverified sources — this protects confidential workforce data.

2. **Locate the current record**
   Search the HRIS by Employee ID (not name, to avoid duplicate-name errors).

3. **Confirm the requested change against supporting documentation**
   E.g., a department transfer should be supported by the approved transfer form or an email from both the losing and gaining manager.

4. **Make the correction in the source system**
   For this portfolio simulation, record the correction as a simulated HRIS update. In a real HR environment, the approved HRIS would be updated as the system of record.

5. **Log the change**
   Note the ticket ID, field changed, old value, new value, and approver in the change log.

6. **Close the ticket with a confirmation note**
   Notify the requestor the correction is complete, and note the effective date if the change affects payroll or reporting.

## Common pitfalls
- In a real HR environment, correcting only a downstream report without correcting the source system can cause the error to reappear in the next reporting cycle.
- Actioning a request without documentation, especially for anything affecting compensation, title, or reporting line.
- Missing the effective date on a change that affects a pay cycle already in progress — flag this to Payroll immediately.
